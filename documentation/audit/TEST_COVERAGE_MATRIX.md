Status di sini adalah status **acceptance lengkap**, bukan penilaian bahwa beberapa assertion parsial sudah ada.

## Arti status

- `PASS`: seluruh skenario minimum dan acceptance pada baris tersebut sudah dijalankan dengan bukti yang disebutkan. PASS hanya berlaku pada environment yang dicatat.
- `FAIL`: eksekusi test menghasilkan pelanggaran acceptance. Temuan statis tanpa eksekusi tidak otomatis dilabeli FAIL.
- `NOT TESTED`: belum ada eksekusi, atau test yang ada hanya mencakup sebagian acceptance. Detail coverage parsial tetap dicatat agar tidak hilang.
- `PENDING DECISION`: expected result, role, kebijakan bisnis, volume, atau budget belum disetujui sehingga status final tidak dapat dikunci.

Tidak ada status `PARTIAL PASS`: coverage parsial tetap `NOT TESTED`. Dengan aturan ini, jumlah PASS tidak boleh dipakai sebagai persentase kesiapan release tanpa membaca kolom gap.

## Gap otomatisasi yang menghalangi release

1. **Concurrency/failpoint:** runner dua server + row-lock barrier dan replay key sudah membuktikan savings withdrawal, duplicate submit, payment periode race, DU publish, fee publish, dan last-admin delete; payment replay single-session juga ada pada regression. Deadlock/retry, concurrent report correction, serta failpoint setiap write masih belum tercakup.
2. **Security breadth:** direct route-role matrix 168/168 sudah tersedia, tetapi belum menjadi Cartesian product seluruh route × method × content-type × parameter × CSRF. Authenticated DAST SQLi/XSS, timeout/deleted/role-changed session, replay lintas domain, dan state oracle per kombinasi masih belum lengkap.
3. **Audit trail:** schema parity/repeat, trigger negative test, dan handler integration sudah diuji pada suite disposable 18/18. Event fixture HTTP memang append-only sebelum clone di-drop; jangan mengklaim cleanup event nol pada database bersama.
4. **Historical upgrade:** matrix membuktikan fresh schema menerima 19 migrasi dua kali; harness recovery 19/19 membuktikan rerun setelah error sintetis pasca-migrasi. Fixture setiap schema historis, privilege deployment target, failpoint di tengah statement, dan failed-midway recovery produksi belum tersedia.
5. **Report/export:** perlu satu oracle yang dibandingkan pada web, print, PDF, dan Excel, termasuk file benar-benar dirender/dibuka, formula inert, leading-zero NIS, empty/boundary, receipt legacy, dan protected rekap kelas.
6. **Performance:** baseline bounded lokal tersedia di `REP-PERF-001`, tetapi belum ada data generator anonim worst-case, budget p95/peak RAM/query/rows examined/ukuran file, maupun concurrent operators. Volume dan budget harus disetujui sebelum TC-PERF-001 atau TC-REP-002 dapat PASS.
7. **Browser/accessibility:** smoke lokal login + enam halaman read-only kini tersedia (`UI-BROWSER-001/002`), tetapi browser discovery resmi untuk UAT penuh tetap kosong; accessibility tree, seluruh role/route, contrast, network/console menyeluruh, dan visual regression belum terbukti.
8. **Disaster recovery/deploy:** restore baseline dan clean-package provisioning lokal sudah lulus dengan schema/migrasi/verifier/auth smoke, tetapi backup terenkripsi, RPO/RTO, rollback, virtual host/HTTPS, dan target client masih kosong.
9. **UAT:** seluruh skenario dalam `UAT_PACKAGE.md` masih PENDING dan belum ditandatangani client. Test teknis tidak boleh mengubahnya menjadi PASS.

## Aturan pembaruan

1. Tambah hasil hanya setelah command, timestamp, commit/worktree state, environment, expected/actual, exit code, dan cleanup tercatat tanpa secret/PII.
2. Bila test hanya menambah satu variasi pada acceptance majemuk, pertahankan `NOT TESTED` dan perbarui coverage parsial; jangan memakai label PASS parsial.
3. `PENDING DECISION` baru dapat diubah setelah decision log mempunyai owner, tanggal, dan acceptance terpilih.
4. Failure environment (schema/server/credential test tidak siap) dicatat sebagai failure run, tetapi status TC tetap `NOT TESTED` bila scenario bisnis belum pernah mulai; failure assertion acceptance harus menjadi `FAIL`.
